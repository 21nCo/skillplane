## Revised requirements

The master superseded the earlier transition design:

- do not authenticate or preserve the previous `sps_...` credential format;
- remove its storage and rotation-as-migration path;
- keep AuthFn as the internal credential implementation without exposing that provider in the agent-credential UI or public service-principal representation;
- gate publication until a new explicit approval is given; that approval was subsequently received.

## Implemented behavior

### One credential path

- Service-principal authentication accepts only current Skillplane agent credentials.
- Requests carrying the removed credential format fail with `401`.
- API and MCP continue to use one shared authentication bridge.
- MCP audit identity is serialized as the provider-neutral `service_principal` kind.

### Destructive schema cutover

- Migration `0016_authfn_service_principal_keys.sql` adds the AuthFn actor mapping and drops `service_principals.credential_hash`.
- No compatibility hash, dual-source constraint, fallback lookup, or migration window remains.
- Existing service-principal rows survive the column removal without a usable credential. The normal rotate action issues a fresh credential for such a row.
- Schema verification continues to require the unique actor-mapping index and its query plan.

### Provider-neutral presentation

- The service-principal API returns only `credentialAvailable`, not a provider name or provider-specific identifier.
- The settings UI shows generic credential availability, rotation, revocation, expiry, and one-time secret guidance.
- The UI no longer displays `AuthFn API key`, provider enums, or migration instructions.
- End-user setup, connection, and security documentation call the value a Skillplane agent credential.
- The obsolete credential-migration guide and navigation entry were removed.

### Lifecycle and security

- Creation, rotation, expiration, revocation, one-time secret handling, workspace binding, roles, scopes, delegation, and audit behavior remain enforced.
- Lifecycle audit metadata uses provider-neutral field names.
- Current redaction and bundle scans recognize only the supported Skillplane credential prefix.
- Previously applied migrations `0014` and `0015` remain immutable historical records; their old redaction expressions are superseded by the final function installed by migration `0016` and do not provide authentication support.
