## Summary

Codex 0.145.0 can complete the initial Skillplane OAuth grant but omits the
RFC 8707 `resource` parameter when rotating an expired refresh token. Skillplane
currently requires the parameter on every token request, so Codex receives
`invalid_request: resource must be provided exactly once` and no MCP tool can
run after the access token expires.

Separately, MCP agents can discover, retrieve, version, and amend existing
skills, but they cannot create skills or manage visibility, archive/restore,
candidate review, amendment policy, or version diffs. Those lifecycle operations
exist in Skillplane's domain and HTTP layers but remain unavailable to the agent
that consumes and improves the skill.

## Requirements

1. Reproduce and root-cause the Codex OAuth refresh failure against production.
2. Accept an omitted `resource` only for a refresh-token grant, deriving the
   effective audience from the stored refresh-token grant. Keep authorization
   and authorization-code exchange strict, reject duplicate resources, reject
   explicit mismatches, and preserve audience-bound access-token validation.
3. Add regression coverage for Codex-compatible refresh, explicit resource
   refresh, missing resource on authorization-code exchange, duplicate resource,
   explicit mismatch, rotation, reuse detection, scope reduction, and audit.
4. Add a replay-safe `skill_create` MCP tool that creates an initial immutable
   published skill version from a bounded canonical file set.
5. Add replay-safe `skill_visibility_update`, `skill_archive`, and
   `skill_restore` MCP tools with optimistic concurrency and durable mutation
   audit.
6. Add `skill_candidates_list`, `skill_candidate_approve`, and
   `skill_candidate_reject` with tenant authorization, deterministic pagination,
   immutable publication semantics, concurrency protection, and durable audit.
7. Add `skill_amendment_policy_get` and `skill_amendment_policy_update` with
   strict policy schemas, owner-only mutation authorization, idempotency, and
   durable audit.
8. Add `skill_versions_diff` for an authorization-filtered comparison of exact
   immutable versions.
9. Preserve `skill_amend` as the only content-evolution mutation for an existing
   skill; do not introduce mutable in-place skill content updates.
10. Enforce least-privilege OAuth/service-principal scopes, tenant isolation,
    caller attribution, bounded inputs, stable typed errors, replay safety,
    filter-bound opaque cursors, and fail-closed auditing across all new tools.
11. Update schemas, conformance, integration, security, documentation,
    production verification, and live tool inventory coverage.
12. Push, deploy, re-authenticate Codex, and verify OAuth refresh plus the full
    skill lifecycle through the production MCP endpoint.

## Acceptance Criteria

- An expired Codex access token can be rotated using its valid stored refresh
  token even when Codex omits `resource`; the newly issued access token remains
  bound to `https://mcp.skillplane.dev/mcp`.
- Missing `resource` is not accepted for authorization or authorization-code
  exchange, and duplicate or explicitly mismatched resource values fail closed.
- An authorized agent can create a skill, discover it, change visibility,
  create an immutable amendment candidate, inspect/diff its versions, review it,
  configure amendment policy, archive it, and restore it using MCP only.
- Viewers and credentials missing the required write scopes cannot mutate skills
  or publication state; cross-workspace selectors reveal no private data.
- Replayed idempotency keys return the original result while changed payloads
  with the same key fail safely.
- Production advertises and successfully executes the complete expanded tool
  catalog after a fresh Codex OAuth connection.
