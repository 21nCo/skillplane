## Summary

The authenticated MCP surface cannot answer a basic request such as "retrieve my
skills" without out-of-band identifiers. It exposes no workspace-discovery tool,
and `skills_search` requires an exact `workspaceId` plus a non-empty full-text
query. Even with the identifier, search is not complete enumeration: it returns
only query matches joined to a current published version.

Skillplane workspace identifiers are also generated as `workspace:<uuid>`, not as
bare UUIDs, so asking a user for a "workspace UUID" is imprecise.

## Requirements

1. Add an authenticated, read-only MCP tool that lists every workspace available
   to the current OAuth user or the single workspace bound to a service principal.
2. Add an authenticated, read-only MCP tool that lists skills in an authorized
   workspace without requiring a search query.
3. The skill listing must be cursor-paginated, filter-bound, and include active
   skills that do not yet have a published version without leaking version content.
4. Workspace selection must accept the stable Skillplane ID or workspace slug.
5. OAuth and service-principal scope checks, tenant isolation, caller attribution,
   durable audit, strict schemas, and stable structured output must remain intact.
6. Multi-workspace discovery must record the disclosure in every returned
   workspace and fail closed if the audit batch cannot be committed atomically.
7. Update conformance, integration, security, schema, documentation, and
   production verification coverage for the new tools.
8. Deploy the MCP Worker and verify the live Codex-facing tool inventory and real
   production behavior.

## Acceptance Criteria

- A connected Codex session can call `workspaces_list` without knowing a
  `workspaceId`.
- It can call `skills_list` with a returned workspace ID or slug and exhaust all
  pages without supplying a text query.
- Service credentials cannot discover or enumerate another workspace.
- OAuth users see only current memberships; no public directory or unrelated
  workspace is silently mixed into "my workspaces."
- `skills_search` remains available for ranked full-text discovery and existing
  callers remain compatible.
- Production verification proves both new tools are advertised and callable.
