## Audit scope

This audit answers one bounded question: which parts of the current UIFn state are suitable for Skillplane's production UI, which parts are not, and what must become true before Skillplane depends on them.

The audit covers:

- UIFn package architecture and framework support.
- Svelte 5 and SvelteKit consumer suitability.
- Headless primitive behavior and generated API typing.
- Styled component completeness.
- Tailwind integration and design-token coverage.
- Accessibility, responsive evidence, and browser coverage.
- Package distribution, versioning, licensing, and runtime compatibility.
- Coverage of the UI-relevant portions of the Skillplane intent and specification.
- A proposed ownership boundary between UIFn and Skillplane's `packages/ui`.

The audit does not claim to verify Skillplane's application features, because implementation has not begun. Requirements unrelated to a UI dependency are marked `N/A (dependency scope)`, not passed.

No UIFn or other Superfunctions source was edited. The full release command generated or refreshed existing UIFn evidence output under `uifn/.conduct`; that output is not a source fix and is excluded from the source fingerprint. The only Skillplane writes from this audit are this report and the append-only audit log row.

### Decision

Skillplane should **not** treat UIFn as its production-ready UI kit today. It may adopt a frozen and repaired subset of the headless packages behind a Skillplane-owned façade. Skillplane must continue to own its design tokens, Tailwind implementation, Phosphor icon conventions, product components, layouts, and product-state behavior.

## Spec conflicts / spec gaps

### SPEC MISSING — immutable UIFn dependency decision

The Skillplane specification correctly requires shared UI to live behind `packages/ui`, but it does not yet decide whether UIFn is:

1. a published dependency,
2. a committed vendored snapshot,
3. exact checked tarballs, or
4. rejected for the initial release.

The current dirty worktree cannot be used as an implicit fifth option. Phase 00 should require an immutable UIFn source reference, integrity data, license record, and rollback plan before Phase 06 imports it.

### SPEC MISSING — permitted package boundary

The specification should explicitly permit only an accepted UIFn subset. Recommended initial allowlist:

- `@uifn/core`
- `@uifn/dom`
- `@uifn/adapter-kit`
- `@uifn/svelte`

Recommended denylist until separately accepted:

- `@uifn/components-svelte`
- `@uifn/theme-tailwind`
- experimental `patterns`
- experimental `sf`
- framework packages not used by Skillplane

This protects Skillplane from accidentally coupling product components to the least mature UIFn surfaces.

### SPEC MISSING — Skillplane-owned typed façade

Phase 06 should state that `packages/ui` owns:

- stable typed Svelte APIs;
- Tailwind classes and semantic tokens;
- Phosphor icon sizing and accessibility rules;
- product loading, empty, error, retry, authorization, and confirmation states;
- product-level tables, diffs, timelines, editors, and app-shell behavior;
- a narrow adapter around any UIFn primitive.

UIFn imports should not escape `packages/ui`.

### SPEC MISSING — UI dependency negative checks

Add CI checks that fail when:

- app or landing code imports UIFn directly;
- denied UIFn packages appear in production dependencies;
- a UIFn package resolves from a mutable local absolute path;
- styled wrappers accept untyped arbitrary properties;
- Tailwind output omits required Skillplane classes;
- a required UIFn primitive lacks SvelteKit SSR, hydration, keyboard, and teardown coverage.

### No direct spec conflict

The recommended boundary does not conflict with the current spec. Phase 06 already assigns the final product-facing component library to Skillplane's `packages/ui`. UIFn should be an internal implementation detail, not a replacement for that package.

## Cross-cutting audits (security/determinism/limits/errors/compat)

### Security — PARTIAL

- No production dangerous HTML sink was found in the relevant UIFn source search; observed `innerHTML` use was confined to a browser harness.
- Relevant packages declare MIT licenses.
- Headless APIs provide structured props and state rather than requiring raw HTML injection.
- The full security/release posture is not proven because the release gate is red, package provenance is not immutable, and current npm distribution is incomplete.
- Skillplane must not treat caller-provided UIFn props or slots as trusted content. Its own sanitization, CSP, link, and content-rendering policies remain mandatory.

### Determinism and provenance — FAIL

- The latest code is not represented by HEAD.
- All inspected packages still declare version `0.0.1`, so version numbers do not identify the audited implementation.
- Registry package availability is incomplete.
- A local absolute worktree dependency would be machine-specific and unreproducible.
- Generated catalog and packaging checks are useful, but they cannot compensate for the absence of an immutable source snapshot.

### Limits and scale — PARTIAL

- UIFn exposes 61 Svelte primitive roots and 419 generated parts, which is ample breadth for Skillplane.
- The public token validator only covers color, radius, density, and motion groups despite wider internal types. It does not provide Skillplane's required spacing, typography, shadow/elevation, or icon-size scales.
- Tailwind output extends semantic colors but does not establish the full utility and component system.
- Product-level limits, pagination behavior, virtualized tables, large audit logs, version diffs, and editor payloads remain Skillplane responsibilities.

### Errors and recovery — FAIL

- Core packages contain typed error machinery and focused tests.
- The browser overlay gate fails with a raw `TypeError` while generically invoking `getProps()` for the FloatingPanel resize handle without its required edge/value.
- The immediate failing path is likely a mismatch between the generic browser harness and a primitive-specific contract, but the styled Svelte wrapper's erased prop types permit consumers to reach the same missing-required-value state.
- Skillplane should not use FloatingPanel and should not expose styled wrapper APIs until the gate is green and required properties remain represented in generated declarations.

### Compatibility — FAIL

- `@uifn/svelte` targets Svelte 5 and passes type/build and a production Vite consumer check.
- The headless package declares Node 20–24 compatibility, while styled/theme packages declare narrower and different ranges such as Node 18–22.
- Node 20 is the safe current intersection for Skillplane if UIFn is adopted.
- UIFn uses npm 10/Turbo; Skillplane uses pnpm/Turbo. This is manageable only through published packages, content-addressed tarballs, or a deliberate vendoring process.
- Current npm checks found old `@uifn/svelte@0.0.1` and `@uifn/core@0.0.1`, while `@uifn/dom@0.0.1`, `@uifn/components-svelte@0.0.1`, and `@uifn/theme@0.0.1` were unavailable. The declared current graph is therefore not coherently installable from npm.
- The support matrix identifies target browser/framework coverage as not yet proven.

### Component and design-system coverage

Useful headless primitives include Dialog, AlertDialog, Select, Combobox, Autocomplete, Menu, Menubar, Tabs, Toast, Tooltip, Popover, Checkbox, RadioGroup, Switch, FileUpload, Pagination, Field, Form, and related disclosure/navigation controls.

Phase 06 components not supplied as complete UIFn components include:

- Textarea
- DataTable
- generic Badge
- Skeleton
- EmptyState
- ErrorState
- CommandMenu / command palette

Skillplane also requires product components that should not belong to a generic primitive library: version diff, amendment timeline, learning-evidence panel, audit table, analytics views, skill editor, context knowledge editor, consent surface, and application shell.

### Styled layer

`uifn/components/styles.css` is a short reset and semantic baseline. It contains useful focus, density, forced-color, and reduced-motion hooks, but it does not define the layout, spacing, typography, geometry, and state styles for a complete component catalog. Inspected 400% evidence visibly renders native/default controls rather than a finished design system.

Every inspected generated `@uifn/components-svelte` wrapper uses a broad property type equivalent to `Record<string, unknown>` plus an optional class. Generated declarations preserve that erasure. The styled package's test command explicitly permits zero tests. These conditions disqualify it as Skillplane's production component contract.

### Tailwind integration

A real Tailwind 3/PostCSS compile using `createTailwindPreset()` produced semantic color classes such as `.bg-uifn-surface-canvas`, but did not produce `.uifn-button` or `.uifn-surface`. The package returns plugin descriptor objects rather than executable Tailwind plugin functions. Its tests validate object shape rather than an actual Tailwind build.

Skillplane's Tailwind implementation must therefore be first-party until UIFn supplies and tests a real compatible integration. Skillplane is free to map stable UIFn state/data attributes to its own Tailwind classes.

### Accessibility and responsive evidence

- Headless primitives include accessibility-oriented roles, keyboard behavior, focus management, forced-color handling, and reduced-motion hooks.
- The support matrix still labels target coverage as not yet proven.
- Manual accessibility evidence is blocked without a human verifier and NVDA coverage.
- The latest final browser evidence reports two failed 400% reflow vectors: Svelte SignaturePad and Solid Progress.
- Those failing primitives are not required for Skillplane's initial product, but they prevent a blanket production-ready certification for the library.

## Recommendations

### Adoption decision

Use UIFn only as a **conditional internal headless dependency**. Do not use it as the Skillplane design system and do not expose UIFn APIs directly from application features.

### Mandatory pre-adoption gates

1. Freeze the desired UIFn source in a clean commit or exact content-addressed package artifacts.
2. Assign meaningful coherent package versions and record integrity/provenance.
3. Make `verify:uifn-release` green, including stable graph, clean, governance, and all overlay browser projects.
4. Publish or otherwise package every dependency required by the accepted Svelte graph.
5. Add a real SvelteKit SSR and hydration consumer for the exact Skillplane primitive subset.
6. Prove keyboard, focus, escape, outside-click, teardown, and reduced-motion behavior for that subset.
7. Either preserve exact styled wrapper types and add behavioral tests, or keep the styled package denied. The latter is recommended.
8. Do not adopt `@uifn/theme-tailwind` until an actual Tailwind compile proves its promised utilities.
9. Resolve the relevant accessibility evidence for the subset and keep Skillplane's own axe, keyboard, responsive, and manual checks.
10. Pin Node 20 until package engine ranges are reconciled.

### Recommended Skillplane package boundary

```text
app/ and landing/
        |
        v
packages/ui  -- Skillplane-owned public component APIs, Tailwind, tokens, Phosphor
        |
        v
packages/ui/internal/uifn  -- narrow adapters, no re-export of raw UIFn APIs
        |
        v
accepted headless UIFn packages only
```

`packages/ui` should own every Phase 06 component. It may implement complex interaction behavior with accepted UIFn primitives, but it must own visual styling and product semantics.
