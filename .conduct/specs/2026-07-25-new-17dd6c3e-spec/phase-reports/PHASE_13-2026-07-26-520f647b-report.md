## Audit and retention model

| Layer | Invariant |
|---|---|
| write path | one central redacting writer; no direct application/domain/OAuth/MCP audit SQL |
| authenticated identity | actor, optional user, and credential are server-derived |
| declared identity | agent, model, client, run, session, and conversation are labeled caller-declared |
| detail class | `detailed_read_90d`, eligible only after 90 days |
| permanent class | mutations, publications, membership, authorization, OAuth/security, retention runs |
| deletion | database trigger requires detailed class, age threshold, and transaction-local retention-job guard |
| rollup | advisory lock plus transactional replace of one workspace/day |
| retention ordering | every affected UTC day is rolled up before detail deletion |
| export | current filters, role/tenant checks, read-time redaction, `private, no-store` |

## Redaction results

The central writer removes or rejects:

- raw prompt, body, skill body/content, instructions;
- OTP, email, token, authorization, cookie, password, and secret keys;
- email-like values;
- bearer and Skillplane credential-like values;
- overly deep, wide, long, or unsupported metadata.

Postgres independently rejects unsafe direct inserts. API exception logs omit
arbitrary messages, DataFn operational logging emits controlled codes only,
and OAuth operational metadata is redacted before emission. The security
fixture retained only the controlled diagnostic and a six-field redaction
count.
