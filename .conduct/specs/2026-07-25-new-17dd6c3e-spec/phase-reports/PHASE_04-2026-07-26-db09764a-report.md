  the role hierarchy.

   the branded invitation template.
2. Test delivery uses the injected SendFn capture provider; production
   configuration cannot select it.
3. Two concurrent invites to one normalized address produced one database row
   and one SendFn transaction.
4. The email link was followed through the browser workflow by a second,
   matching AuthFn user.
5. Acceptance created one membership, and reuse/reload showed the terminal
   used state.
6. Mismatched, expired, revoked, and reused invitations fail without a
   membership write.

Postgres stores the recipient as a versioned AES-GCM envelope plus an HMAC
lookup and stores only the SHA-256 invitation-token digest.

## Defects closed

1. A combined Postgres constraint drop and column rename was invalid syntax.
   The transaction rolled back and the migration was corrected before
   application.
2. Fixture cleanup initially violated the personal-owner foreign key. Cleanup
   now removes every fixture-owned workspace before its AuthFn user.
3. Cookie-authenticated mutations could skip CSRF when an unrelated
   Authorization header was present. Only bearer-only or authenticated-service
   requests may skip cookie CSRF.
4. Raw invitation paths could have entered rate-limit bucket input. Dynamic
   invitation tokens are normalized to fixed route templates before hashing.
5. Concurrent invitations required a database-enforced active-recipient
   invariant. Migration `0007` supplies the partial unique index.
6. The mobile screenshot initially captured an entering drawer. The browser
   assertion now waits for 90 percent viewport intersection.
7. Vitest could discover built and Playwright outputs. Package scripts now
   constrain source/integration/security roots and exclude `dist`.
8. Migration manifest assertions still expected five migrations. They now
   assert the full seven-migration chain.
