## Requirements delivered

`CTX-001`, `CTX-002`, `CTX-003`, `CTX-005`, `AUTH-004`, `UI-002`, `UI-004`,
`UI-005`, `QA-002`, and `QA-004`.

### Context model and lifecycle — PASS

- Supports `repository`, `project`, `customer`, `environment`, and `custom`
  context types.
- Context slug uniqueness is scoped to a skill, and context lookup binds both
  skill and slug.
- Name, description, external reference, bounded JSON metadata, active/archive
  filtering, archive, and restore are complete.
- Creating a context atomically creates knowledge revision 1.
- Limits enforce 100 contexts per skill, 500 active notes per context,
  512-KiB knowledge, 256-KiB notes, and 32-KiB/depth-8/key-200 metadata.

### Immutable knowledge and notes — PASS

- Knowledge and notes store append-only revisions with sequence, same-parent
  base link, SHA-256 digest, learning metadata, actor/user identity, optional
  agent/model declarations, and timestamps.
- Expected-revision checks and row locks prevent silent last-write-wins.
- Context, knowledge, note creation, note/knowledge amendments, profile
  updates, and lifecycle mutations require idempotency keys.
- Exact idempotent replay returns the original result; mismatched key reuse
  returns a typed conflict.
- Database triggers reject revision update/delete operations.

### DataFn and API — PASS

- Hono exposes authorized context list/create/get/update/archive/restore,
  knowledge current/history/amend, and note
  list/get/create/update/history/archive routes.
- DataFn exposes typed tenant-filtered context, knowledge revision, note, and
  note revision reads.
- Concurrency-sensitive writes deliberately remain in domain services behind
  Hono instead of bypassing invariants through generic DataFn mutation.
- Cross-workspace and cross-skill lookups return non-leaking `404` responses.

### UI and accessibility — PASS

- Context inventory, creation, detail, profile editing, shared knowledge,
  named notes, exact source, safe Markdown, learning metadata, revision
  history, conflict recovery, lifecycle filters, and confirmations are
  complete.
- Loading, empty, validation, success, error/retry, conflict, authorization,
  active/archive, and destructive confirmation states are distinct.
- Viewers receive complete read access with mutation controls omitted.
- Axe found zero violations on four route families at three viewports in both
  themes, with keyboard focus and overflow checks.
