## Security and observability

- Private and error responses are `no-store`; public hashed assets are
  immutable; private APIs do not emit wildcard CORS.
- DataFn requires production authentication and returns `401`, not an early
  uncached `500`, for anonymous calls.
- MCP advertises a standards-compliant bearer challenge and validates resource
  audience.
- Turnstile is restricted to `app.skillplane.dev`.
- Only the app Worker can send email or validate OTP/Turnstile; MCP and landing
  have least-authority bindings.
- Release evidence is sanitized and contains no secret, database password,
  bearer token, OTP, session cookie, or controlled recipient.

## Deviations and decisions

Cloudflare rejected an apex Worker Custom Domain because `skillplane.dev`
already has an externally managed apex origin record. That record was preserved.
The landing Worker instead owns the full proxied zone route
`skillplane.dev/*`, which retains Cloudflare TLS and routes every apex path.
App and MCP continue to use Custom Domains. Production configuration validation,
dry-run tests, deployment manifests, and runbooks encode this mixed topology.

Native OAuth form posts do not include an `Origin` header. SvelteKit's form
origin protection remains enabled, while AuthFn accepts these native posts and
continues to validate state, client, redirect URI, PKCE, expiry, and one-time
authorization-code use.
