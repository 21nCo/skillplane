---
title: Agent credential migration
description: Rotate legacy sps credentials onto AuthFn API keys and retire the compatibility path safely.
---

New Skillplane agent credentials are AuthFn API keys with an `spk_...` secret.
AuthFn owns secret hashing, authentication, expiry, and revocation. Skillplane
maps the authenticated API-key actor to a service principal and continues to own
its workspace, role, scopes, delegated user, amendment policy, and audit history.

## Compatibility window

Existing `sps_...` credentials cannot be converted in place because Skillplane
does not retain their raw secrets. They continue to authenticate through the
legacy compatibility path until an administrator rotates or revokes them.

To migrate one credential:

1. Open **Settings → Agent credentials**.
2. Rotate the legacy credential. The one-time replacement starts with `spk_`.
3. Update the automation's secret manager and restart the client.
4. Confirm the client can call `workspaces_list` and its required scoped tools.
5. Delete the old secret from the external secret manager. Rotation has already
   invalidated it in Skillplane.

Rotation clears the legacy hash, links the service principal to the new AuthFn
API-key actor, increments the credential version, and records a permanent audit
event. The service principal ID and all Skillplane authorization policy remain
unchanged.

## Operator checks

Count active legacy credentials without reading credential material:

```sql
SELECT count(*) AS active_legacy_credentials
FROM service_principals
WHERE credential_hash IS NOT NULL
  AND revoked_at IS NULL;
```

List the non-secret principals that still need rotation:

```sql
SELECT id, workspace_id, name, last_used_at, expires_at
FROM service_principals
WHERE credential_hash IS NOT NULL
  AND revoked_at IS NULL
ORDER BY last_used_at DESC NULLS LAST, id;
```

Before removing compatibility code, require all of the following:

- the active legacy count is zero;
- no `service_principal_legacy` credential appears in audit monitoring for the
  agreed observation period;
- every long-running automation has passed a scoped MCP smoke with its `spk_`
  replacement; and
- the database backup and rollback procedure has been verified for the release.

After those gates pass, remove `sps_...` recognition and the nullable
`service_principals.credential_hash` column in a forward migration. Do not expose
or export hashes as part of the transition.
